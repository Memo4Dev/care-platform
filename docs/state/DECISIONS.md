- ADR-0001 (error code → HTTP status mapping) proposed; implementation follows it in packages/contracts; awaiting human ratification at next checkpoint before promoting into docs/architecture/62-error-codes.md
- M1-002 defines the conventional error-code → HTTP status mapping in `@commerce-platform/contracts` (documented table in code/README): authn/device-credential → 401, payment execution outcomes only → 402, authz/policy/approval/entitlement/quota gating → 403, not-found → 404, aggregate/state/idempotency/insufficiency conflicts → 409, business-rule-invalid request content → 422, downstream provider failure → 502, unmapped fallback → 500; `62-error-codes.md` remains authoritative for the code list itself
- M1-002 pins money/quantity boundary representation to decimal strings via `moneyAmountSchema`; JS numbers are rejected at the contract boundary to prevent float precision loss (`61-dto-contracts.md`)
- M1-003 treats same-state lifecycle transitions as errors: activating an ACTIVE or suspending a SUSPENDED organization raises OPERATION_NOT_ALLOWED (no silent idempotent no-op for organization status), per task decision; DeactivateWarehouse is the one accepted repeatable write (deactivating an inactive warehouse is a no-op that emits nothing) and deactivating the last ACTIVE warehouse of a branch is allowed because no architecture rule forbids it
- M1-003 keeps Branch/Warehouse as ENTITIES inside the Organization aggregate boundary, mutated only through root commands; the DB UNIQUE constraints remain the concurrent-writer authority while in-memory guards give fast feedback
- M1-003 event naming follows docs/architecture/10-organization.md verbatim (`OrganizationPolicyChanged`, `BranchPriorityChanged`, etc.) and adds lifecycle events OrganizationActivated/OrganizationSuspended plus WarehouseDeactivated required by the command set
