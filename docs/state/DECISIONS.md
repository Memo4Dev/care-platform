# Decisions

- Greenfield repository
- pnpm + Turborepo
- NestJS + Fastify
- PostgreSQL + Drizzle
- Redis + BullMQ
- Supabase Auth
- Next.js + React + TypeScript + Tailwind
- Tauri 2 POS, Flutter deferred
- Cloudflare R2
- REST + OpenAPI
- human approval required for push/merge
- all required gates must be green
- M0-001 bootstraps only the root workspace, shared TypeScript config, `packages/config`, and a lightweight `apps/api` shell; framework-specific app scaffolds and quality tooling are deferred to subsequent M0 tasks
- M0-002 establishes the initial runnable quality baseline for the current scaffold using Prettier, ESLint, TypeScript, and Vitest, while keeping broader monorepo orchestration expansion for later tasks
- M0-003 provides local-only Docker Compose services for PostgreSQL and Redis, with persistent volumes and health checks, without introducing application containers
- M0-004 adds a baseline GitHub Actions workflow that installs dependencies and runs format, lint, typecheck, test, and build for the currently bootstrapped workspace
- M0-004 reopened after remote GitHub Actions failure; CI bootstrap order was fixed to configure pnpm before setup-node pnpm caching, action majors were updated to supported versions, and push triggers were added for `feature/**`
- Milestones including CI are not fully accepted until remote GitHub Actions are green after human-approved push; if red, reopen the relevant task and rerun fix/review/test loop
- M0 remote GitHub Actions is green after push; milestone acceptance is now finalized
- M0-005 establishes the minimal real NestJS + Fastify modular-monolith API shell with `AppModule`, module baseline, and shell-safe `GET /health` endpoint without DB/Redis coupling
- Development environment constraint (human-directed): local machine is macOS 13.7.8 Intel with NO local container runtime; do not install/require Docker, Colima, Lima or QEMU for local development; use native PostgreSQL (Homebrew postgresql@16 on localhost:5433, database `care_platform_test`) and native Redis when M1+ requires them; integration tests must support a native-service path via `TEST_DATABASE_URL`-style env config locally while keeping Testcontainers/service-container execution in GitHub Actions CI; Docker Compose remains for VPS/staging only; local Docker availability is never a prerequisite for M1 tasks
- M1-002 adds packages/contracts as the shared dependency-free (zod-only) contract package: full 70-code stable error catalog + PlatformError + API envelope/cursor pagination primitives; pagination wire param is `after` per 51-api-conventions
- ADR-0001 (error code → HTTP status mapping) proposed; implementation follows it in packages/contracts; awaiting human ratification at next checkpoint before promoting into docs/architecture/62-error-codes.md
- M1-002 defines the conventional error-code → HTTP status mapping in `@commerce-platform/contracts` (documented table in code/README): authn/device-credential → 401, payment execution outcomes only → 402, authz/policy/approval/entitlement/quota gating → 403, not-found → 404, aggregate/state/idempotency/insufficiency conflicts → 409, business-rule-invalid request content → 422, downstream provider failure → 502, unmapped fallback → 500; `62-error-codes.md` remains authoritative for the code list itself
- M1-002 pins money/quantity boundary representation to decimal strings via `moneyAmountSchema`; JS numbers are rejected at the contract boundary to prevent float precision loss (`61-dto-contracts.md`)
